AGENT_SPEC.md — Autonomous Build Specification for SmartCity3601. Role & ObjectiveYou are a Principal Java Architect and Autonomous Coding Agent working for UrbanTech Solutions. Your mission is to build, test, and document SmartCity360 – A Smart City Management Platform as a modular Java 17 + Java Swing (FlatLaf) desktop application that demonstrates five Gang of Four (GoF) Object-Oriented Design Patterns:Part A: Decorator Pattern – Dynamic Security Wrappers for Energy Meter Data Streams.Part B: Composite Pattern – Hierarchical Structure of Smart Zones (City -> District -> Street -> Building).Part C: Chain of Responsibility Pattern – Dynamic Escalation of Citizen Complaints.Part D: Flyweight Pattern – Memory-Efficient Management of Thousands of Smart Streetlights.Part E: Interpreter Pattern – Parsing and Evaluating City Operational Policies Defined in a Mini-DSL.2. Non-Negotiable Architectural RulesStrict GoF Pattern Fidelity: Never fake a design pattern inside a Swing UI listener. Each pattern MUST be implemented in its own isolated domain package with clean interfaces, abstract classes, and concrete implementations that match classic GoF UML structures.Zero External Server Dependencies: Use pure Java 17+, Swing, FlatLaf (com.formdev:flatlaf:3.4), and JUnit 5 (org.junit.jupiter:junit-jupiter:5.10.2). The project must build and run out-of-the-box on any machine via mvn clean test and mvn exec:java.Observable Execution Traces: Every pattern method call must generate clear, human-readable trace messages (e.g., [AuthDecorator] Signed payload with HMAC-SHA256 signature) so both the automated tests and the Swing UI log panels can display the exact runtime execution path during the video demonstration and VIVA.Self-Contained Zip Packaging: Configure maven-shade-plugin or exec-maven-plugin in pom.xml so the student can run the application with one click or command.3. Pattern ImplementationsModule A – partA_decorator (Decorator Pattern)Problem Solved: Dynamically wrap energy meter telemetry streams with arbitrary combinations and orderings of Encryption, Authentication, and Compression without altering EnergyMeterStream.Classes to Implement:DataStream (Interface):String transmit();List<String> getExecutionTrace();String getLayerDescription();EnergyMeterStream (ConcreteComponent implementing DataStream):Fields: String meterId, double kilowattHours, String timestamp.transmit() returns raw JSON-like payload, e.g., {"meterId":"MTR-104","kWh":42.8,"ts":"2026-11-07T21:00Z"} and records base trace step.StreamDecorator (Abstract Decorator implementing DataStream):Field: protected final DataStream wrappedStream;Constructor accepts DataStream wrappedStream and delegates calls by default.EncryptionDecorator (ConcreteDecorator extending StreamDecorator):Wraps wrappedStream.transmit() by applying simulated AES-256 / Base64 cipher transformation (ENC[AES256](...)) and appends a detailed trace entry.AuthenticationDecorator (ConcreteDecorator extending StreamDecorator):Appends an HMAC-SHA256 token header (AUTH[HMAC=<hash>]|...) to the result of wrappedStream.transmit() and appends a trace entry.CompressionDecorator (ConcreteDecorator extending StreamDecorator):Compresses payload representation (COMP[GZIP,ratio=64%](...)), calculates byte size reduction, and appends a trace entry.Module B – partB_composite (Composite Pattern)Problem Solved: Represent City -> District -> Street -> Building as a recursive tree hierarchy so commands like shutdownPower(), restorePower(), and reportUsage() execute uniformly on both single buildings (Leaves) and entire districts/cities (Composites).Classes to Implement:ZoneType (Enum): CITY, DISTRICT, STREET, BUILDING.SmartZoneComponent (Abstract Class or Interface):String getName();ZoneType getZoneType();double getPowerUsageKw();void shutdownPower(List<String> traceLog);void restorePower(List<String> traceLog);String reportUsage(int indentLevel);Default add(SmartZoneComponent c) and remove(SmartZoneComponent c) throwing UnsupportedOperationException for leaves.BuildingLeaf (Leaf extending SmartZoneComponent):Fields: String name, String buildingCategory, double nominalKw, boolean powerActive.When powerActive == false, getPowerUsageKw() returns 0.0.shutdownPower() sets powerActive = false and logs [LEAF-BUILDING] <name>: Main breaker opened (0.0 kW).ZoneComposite (Composite extending SmartZoneComponent):Fields: String name, ZoneType zoneType, List<SmartZoneComponent> children = new ArrayList<>().getPowerUsageKw() recursively sums child.getPowerUsageKw() across all children.shutdownPower(traceLog) logs composite broadcast and recursively invokes child.shutdownPower(traceLog) on all children.reportUsage(indentLevel) builds a formatted hierarchical tree report showing aggregated kW at each composite node and individual kW at each leaf.Module C – partC_chain (Chain of Responsibility Pattern)Problem Solved: Route citizen complaints dynamically along an authority chain (Local Staff -> Supervisor -> City Manager) based on severity level, decoupling the citizen submission portal from concrete handlers.Classes to Implement:SeverityLevel (Enum):LOW(1, "Minor Local Issue"), MEDIUM(2, "District Service Disruption"), HIGH(3, "Critical City Infrastructure Emergency"), EXTREME(4, "Unclassified / National Escalation").ComplaintRequest (Immutable Model):Fields: String complaintId, String citizenName, String category, String description, SeverityLevel severity.ComplaintResolution (Result Model):Fields: boolean handled, String handledByRole, String actionTaken, List<String> escalationTrail.ComplaintHandler (Abstract Handler):Fields: protected ComplaintHandler nextHandler;, protected String handlerName;, protected boolean active = true;Method: public ComplaintHandler setNextHandler(ComplaintHandler next) (returns next for fluent chaining).Method: public final ComplaintResolution handle(ComplaintRequest request, List<String> trail) — checks if active && canHandle(request). If true, processes it; otherwise logs escalation reason and passes to nextHandler. If nextHandler == null, returns an unhandled/fallback escalation notice cleanly.Concrete Handlers:LocalStaffHandler (Handles SeverityLevel.LOW — e.g., overflowing bin, minor pothole).SupervisorHandler (Handles SeverityLevel.MEDIUM — e.g., street outage, water main leak).CityManagerHandler (Handles SeverityLevel.HIGH — e.g., grid substation failure, major emergency).Module D – partD_flyweight (Flyweight Pattern)Problem Solved: Manage 50,000+ smart streetlights across the city with minimal heap memory by separating shared intrinsic hardware profile data from unique extrinsic pole coordinates and runtime dimming state.Classes to Implement:StreetLightFlyweight (Interface):String renderOperation(String poleId, double lat, double lon, boolean isOn, int dimmingPercent);String getIntrinsicSummary();long getApproximateIntrinsicBytes();SharedLightModel (ConcreteFlyweight implementing StreetLightFlyweight):Intrinsic State (Immutable & Shared): String modelCode, String manufacturer, int wattage, int lumens, int colorTempK, byte[] firmwareLutPayload (e.g., a new byte[2048] photometric lookup curve simulating heavy shared configuration data).Constructor has package-private visibility so clients MUST obtain instances through StreetLightFactory.StreetLightFactory (FlyweightFactory):Field: private static final Map<String, StreetLightFlyweight> FLYWEIGHT_POOL = new ConcurrentHashMap<>();Method: getLightModel(String modelCode, String manufacturer, int wattage, int lumens, int colorTempK) — returns cached instance or creates and caches a new one.Method: int getPoolSize(), Map<String, StreetLightFlyweight> getCachedModels().StreetLightContext (Client Context Object):Extrinsic State (Unique per pole): String poleId, String streetName, double latitude, double longitude, boolean poweredOn, int brightnessPercent.Reference: private final StreetLightFlyweight sharedModel; (only an 8-byte object reference!).MemoryBenchmarkService:Simulates creating $N$ streetlights (e.g., $N = 10,000$, $50,000$, or $100,000$) using the StreetLightFactory pool versus what naive unshared objects (each duplicating the 2 KB firmware/photometric profile + metadata strings) would consume:
$$\text{Memory}_{\text{Unoptimized}} = N \times (\text{IntrinsicSize} + \text{ExtrinsicSize})$$$$\text{Memory}_{\text{Flyweight}} = (K \times \text{IntrinsicSize}) + (N \times \text{ExtrinsicSize})$$
where $K \ll N$ is the small number of unique streetlight models (e.g., $K = 4$).Module E – partE_interpreter (Interpreter Pattern)Problem Solved: Parse and evaluate dynamic city operational policy
